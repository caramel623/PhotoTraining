# Vehicle Dataset Manager

Windows 本地車輛影像資料集建立與人工複核工具，提供繁體中文介面。可從 ZIP／7Z 匯入照片及同名 INI，執行車輛偵測、車牌 OCR、候選分組，最後匯出車牌遮罩後的 Vehicle Re-ID 訓練資料。

**照片、車牌與資料庫留在本機。INI 或 OCR 的同車牌分組只是候選，不等於人工確認同一台車。**

[下載 Windows 發行版](https://github.com/caramel623/PhotoTraining/releases) · [問題回報](https://github.com/caramel623/PhotoTraining/issues) · [原始規格](docs/PROJECT_SPECIFICATION.md)

## 1. 安裝與第一次啟動

1. 從 Releases 下載 Windows x64 ZIP，完整解壓到可寫入的資料夾，例如 `E:\VehicleDatasetManager`。
2. 執行 `VehicleDatasetManager.exe`。不要只複製 EXE；同層的 `_internal`、`models` 等目錄也必須保留。
3. 預設工作區就是 EXE 所在資料夾。請勿放在唯讀目錄、壓縮檔內或受保護的 Program Files。
4. 開啟「設定」，確認模型與運算裝置，完成下一節的依賴安裝。
5. 安裝後重新啟動，再從「匯入」開始操作。

發行版採用資料夾式封裝，不是大型單一 EXE。Windows 主程式不要求另裝 Python；OCR 的獨立環境則需要 Python 3.13，安裝功能會協助準備。

若要指定另一個工作區，可在 PowerShell 執行：

```powershell
& "E:\VehicleDatasetManager\VehicleDatasetManager.exe" --workspace "E:\VehicleWorkspace"
```

既有設定若已指定工作區，請檢查「專案資訊」確認實際使用位置，避免誤以為原資料不見了。

## 2. 安裝 OCR、車牌模型與 GPU 依賴

在「設定」使用 **下載／安裝所有必要依賴與 OCR 模型**，並查看安裝日誌：

- 缺少 Python 3.13 時，透過 Windows winget 安裝使用者層級 Python。
- 建立程式旁的 `.venv-ocr`，安裝 PaddleOCR 所需套件。
- 依所選的 mobile／server 預設下載 OCR 模型，執行自我檢查。
- 發行包已包含專案指定的台灣車牌 ONNX 偵測權重；安裝成功後自動選用。
- 偵測到 NVIDIA GPU 時接續準備 CUDA runtime；沒有 NVIDIA 時保留 CPU 模式。
- Re-ID 模型不是 OCR 模型，仍需另外提供適合的 ONNX 權重與前處理設定。

首次安裝需網路與足夠磁碟空間；CUDA 依賴可能需要數 GB。此處的連線用途是下載套件／模型，不是上傳照片。安裝完成後請重啟程式，再按「偵測環境」確認結果。

若顯示「CPU 版 PyTorch」，有 NVIDIA GPU 也不代表 CUDA 已啟用。封裝版請使用設定頁的安裝按鈕，**不要執行 `VehicleDatasetManager.exe -m pip ...`**。

車牌權重授權與來源見 [MODEL_LICENSE.txt](models/MODEL_LICENSE.txt)。權重放入發行 ZIP，但不提交到 Git 原始碼。A5000 的實際 GPU 加速仍需在目標電腦驗證；本專案測試不代表已完成所有顯示卡的相容性驗證。

## 3. 匯入照片與 INI

1. 切到「匯入」，按「加入壓縮檔…」，或加入含壓縮檔的資料夾。
2. 支援 ZIP、7Z 及巢狀壓縮檔；照片支援 JPG、JPEG、PNG，副檔名大小寫不影響配對。
3. 年份選「自動」可從壓縮檔名推斷；需要時手動指定。
4. 第一次使用「一般匯入」，按「開始匯入／重新掃描」。
5. 查看結果表；將游標停在壓縮檔名稱可查看額外統計。「檢視最近匯入／重掃紀錄」保留最近 100 筆操作的完整統計。

INI 必須與照片位於同一個解壓後目錄且同名，例如：

```text
cam/
  20260910_080000_000_RS001_0001_A.JPG
  20260910_080000_000_RS001_0001_A.INI
```

以下是完全虛構的 INI 示例：

```ini
主機=RS001
地點=測試路段
影像序號=0001
日期=2026/09/10
時間=08:00:00
速限=030km/h
車速=040km/h
方向=車尾
方向=1
車種=2
違規=13
車號=TST-1234
```

解析支援 UTF-8、UTF-8 BOM、CP950／Big5。重複的「方向」會分別保存文字與代碼；原始行、重複鍵和警告也會保存。多個不同車號不會隨便選一個當成可信標籤。INI 不會套用 OCR 的 O／0 等字元猜測。

缺少 INI 不會阻止影像匯入；只有 INI 而沒有照片則列為未配對。INI 日期、時間、相機與影像序號和檔名不同時會留下品質警告，供人工查核。

## 4. 舊資料升級與重新掃描（重要）

**「壓縮檔已匯入」與「已用新版解析器掃描」是兩件不同的事。** 即使檔案大小、時間與 SHA256 都沒變，更新解析器後仍會重新掃描 metadata，不會因 archive 已存在就直接跳過。

| 模式 | 新增影像 | 更新 metadata | 自動重跑偵測／OCR／Re-ID |
|---|---|---|---|
| 一般匯入 | 有新內容才新增 | 是 | 否；新影像等待手動開始處理 |
| 重新掃描既有資料 | 不新增 | 是，僅更新已識別的既有影像 | 否 |
| 強制重解析 INI／metadata | 可新增 | 是，重新讀取解析 | 否 |

將舊資料補上 INI 的操作：

1. 關閉程式，備份整個工作區，尤其是 `database` 與 `settings.json`。
2. 啟動新版，使用原工作區；資料庫會自動遷移，不必刪除重建。
3. 加入原本匯入的 ZIP／7Z，選「重新掃描既有資料」。
4. **在清單選取要重掃的壓縮檔**，可用 Ctrl／Shift 多選，然後開始。
5. 檢查「既有」「新增」「INI 配對」「Metadata 更新」「衝突」與完整歷史紀錄。
6. 到「人工複核」檢查 INI／OCR 衝突。

影像以 SHA256 識別，壓縮檔改名、重新壓縮或 ZIP 換成 7Z，只要影像位元組相同就沿用影像記錄並增加來源。相同檔名但不同內容則是不同影像，不會覆寫舊解壓資產。

舊版沒有 SHA256 的記錄會從仍存在的本地影像補算；原檔已遺失時無法安全確認身分，不會只靠同名硬合併。請先恢復原工作區的解壓影像。

「取消目前工作」採協作式取消。每張成功合併的影像會形成一個完整交易；重跑可接續未完成部分。單筆失敗會回復該筆並留下錯誤，已成功的資料保留。大型 7Z 解壓期間可能要等目前解壓階段結束才回應取消。不要因等待而刪除資料庫。

目前重掃仍會讀取壓縮檔與 metadata；省下的是重新執行 AI，不代表大壓縮檔能瞬間完成。內容版本不同的解壓快照會保留，因此要預留磁碟空間。

## 5. 影像處理

1. 確認設定中的車輛偵測器、車牌偵測器與 OCR 已可用並儲存設定。
2. 切到「影像處理」，按「處理全部待辦影像」，或選工作後「繼續選取的工作」。
3. 程式依序讀取影像、取得 metadata、偵測車輛、裁切、偵測／辨識車牌、建立候選群組。
4. 需要暫停可按「取消」；再執行時只處理待辦，已完成影像不會因重掃 metadata 而重算。
5. 失敗項目先查「日誌」和模型設定，再使用「重試失敗項目」。

正式大量處理前先準備最多 100 張的測試壓縮檔，確認車輛裁切、車牌框與 OCR 合理。匯入成功不代表 AI 模型已安裝或辨識品質已達標。

## 6. 標籤優先序與人工複核

有效車牌優先順序：**人工修改 > 合法 INI 車號 > OCR > 無車牌**。INI 原始車號、OCR 結果及人工文字分開保存，OCR 不會覆蓋人工或有效 INI。

在「人工複核」可看到 INI 車牌、OCR 車牌、有效車牌、來源、驗證狀態，以及地點／日期／時間／方向／速度等 metadata。將游標停在 metadata 說明可查看各壓縮檔的 INI 原始資料與警告。

- `MATCH`：來源比對一致。
- `OCR_MISMATCH`：INI 與 OCR 不同，仍以有效 INI 為準，待人檢查。
- `MANUAL_INI_MISMATCH`：人工與 INI 不同，保留人工值並提示。
- `INI_SOURCE_PLATE_MISMATCH`：同一影像的不同來源 INI 有不同車牌，保留既有效值與各來源，禁止自動搬動群組。

群組篩選選擇 **INI／OCR 衝突佇列（含未分組影像）**，即可找到沒有群組的問題影像。此佇列不是一個真實車輛群組，不能整批確認、合併或拆分；可修改車牌、標記不確定或排除。來源不一致的警告可能持續保留，人工車牌仍有最高優先權；確認前建議排除不可靠資料。

一般群組操作與快捷鍵：

| 操作 | 快捷鍵 |
|---|---|
| 確認同一車輛 | Enter |
| 下一張 | Space |
| 非同一車輛 | N |
| 不確定 | U |
| 排除 | X |
| 修改車牌 | E |
| 合併群組 | M |
| 拆分選取影像 | S |

有效 INI 車牌可建立來源為 `plate_ini_exact` 的自動候選。重新掃描可以更新未人工處理的候選，但不會還原人工合併／拆分、搬動已確認群組或清除排除狀態、複核註記。

## 7. 匯出訓練資料集

1. 先完成複核，排除車輛裁切錯誤、標籤不確定與衝突未釐清的影像。
2. 到「資料集匯出」選擇輸出位置及標籤政策。正式訓練優先選人工確認資料。
3. 選車牌遮罩方式：純色、模糊或影像修補。車牌遮罩不足時，不能假定 Re-ID 已不依賴車牌。
4. 選是否複製原始影像；輸出資料可能包含車牌與來源 metadata，**不能直接當成匿名公開資料**。
5. 選群組雜湊、時間或相機切分，先預覽可匯出數量，再匯出。
6. 檢查輸出中的裁切、manifest、切分結果及 positive／negative pairs、triplets。

Re-ID 的視覺輸入是車牌遮罩後的車輛裁切，不是車牌字串。manifest 會保留有效車牌及來源／驗證資訊作為標籤追蹤，而不是把文字送進外觀模型。

切分以車輛群組為單位避免同群組跨集合；如果同一真實車輛被錯分成多個群組，仍可能資料洩漏，因此人工複核不可省略。沒有完整裁切或遮罩條件的影像可能被跳過，請查看匯出報告。

## 8. Re-ID 索引與 Phase 6

提供相容的 Re-ID ONNX 模型後，在「設定」填入模型與正確的輸入尺寸／正規化設定，再由資料集頁建立索引。ONNX 模型並非任意互換，前處理必須與訓練設定一致。

專案包含 ONNX embedding、portable cosine 索引，以及 AI02 Docker／FAISS 部署交接。這不代表已完成正式模型訓練，也不代表 AI02 RTX A5000 的實機部署驗證已完成。詳見 [PHASE6.md](PHASE6.md)。

## 9. 資料位置、備份與更新

| 工作區項目 | 用途 |
|---|---|
| `database/vehicle_dataset.db` | 影像、來源、INI、群組、複核及工作紀錄 |
| `extracted/` | 解壓後影像、INI 與內容版本快照 |
| `crops/`、`plates/` | 衍生裁切 |
| `exports/`、`reid/` | 匯出資料與索引 |
| `logs/` | 日誌，可能包含私人路徑或 metadata |
| `settings.json` | 本機設定 |
| `models/`、`.venv-ocr/`、`cuda-runtime/` | 模型與執行環境 |

更新前關閉程式並備份完整工作區。若直接使用 EXE 目錄當工作區，更新時保留上述資料，不要以整個新資料夾取代舊工作區。資料庫升級後若要退回舊程式，應恢復升級前備份，不要讓舊程式混用新版資料庫。

原始 ZIP／7Z 不會被修改。不要自行刪除解壓資料來「修復」匯入；舊記錄、裁切來源與雜湊補算可能仍依賴它們。

## 10. 常見問題

- **OCR 沒有結果**：檢查依賴安裝日誌、OCR 是否啟用，以及車牌偵測模型是否選到發行包權重；安裝後重啟。
- **CUDA 仍不可用**：先確認 NVIDIA 驅動與環境診斷；不要對 EXE 使用 Python 的 `-m pip` 參數。
- **重掃新增是 0**：既有資料模式本來就不新增。請查看「既有」「INI 配對」「資料更新」，而不是只看新增數。
- **重掃更新也是 0**：資料已一致是正常結果；來源紀錄和匯入歷史仍會保留。
- **衝突為何不自動選一個**：避免用錯誤 INI 覆蓋人工標籤，或把人工拆分的車輛重新合併。
- **看不到舊資料**：查看「專案資訊」的工作區位置，確認未啟動到另一個空工作區。
- **設定擠在一起**：設定內容可垂直捲動，儲存按鈕固定在底部。
- **需要回報問題**：提供版本、操作步驟及去識別化錯誤訊息；勿把照片、INI、完整 DB、日誌或含私人路徑的截圖直接貼到公開 Issue。

## 11. 從原始碼執行與測試

```powershell
git clone https://github.com/caramel623/PhotoTraining.git
cd PhotoTraining
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py --workspace ".\workspace"
.venv\Scripts\python.exe -m pytest -p no:cacheprovider --basetemp .tmp\pytest
```

測試使用合成影像及模擬模型；不需要私人照片。建置 Windows 資料夾版：

```powershell
.\build_windows.ps1
```

建置需要本機已授權的台灣車牌模型。可用 `VDM_PLATE_MODEL_SOURCE` 指定來源；腳本會核對 SHA256。不要使用 `-OneFile` 製作本專案的標準發行包。

目前版本 **v0.0.6**：INI 結構化解析、多來源追蹤、解析器版本感知重掃、逐影像交易續跑、人工資料保護與衝突複核入口。詳細驗證與限制見 [交接文件](HANDOFF_2026-09-12_INI.md)。
